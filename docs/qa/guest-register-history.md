# Guest register and returning check-in

The Check-in header opens the existing Guests workspace as a professional guest register. Each stay has its own row, with search, entry-month/status filters, 50-row pagination, a full record dialog, private ID previews, Excel and print. Guest profiles remain available below the sheet. New entries include a personal-details snapshot in the existing registration JSON; older entries use issued guest identity where available, then the saved profile. Missing historical gender is left unknown rather than inferred.

Selecting a returning guest restores personal/travel details, guest counts, named companions and their foreign metadata. Both sides of each retained ID are reused only after checking the existing authenticated document list and person reference. Deleted/missing copies stay required. Selection versions and explicit photo edits protect against delayed lookups attaching the wrong or deliberately removed photo. Current dates, room/rent and advances remain current-stay decisions. Existing consent and validation remain required.

Foreign details can close from the toggle, top or bottom. A blank accidental form turns off; a filled form collapses without changing nationality or discarding values. Validation reopens a collapsed section at the missing field. Switching to Indian guest explicitly disables foreign requirements. The official old Form C page announces migration and links to https://indianfrro.gov.in/formIII/ ; both foreign reporting links use that destination, with a copy/select fallback inside the form. Bite does not submit official reporting.

Close check-in supports keeping typed draft details or discarding an unsent form. Pending commands cannot be discarded. Unsaved local photos must be selected again after draft resume; retained copies remain available. No production record is created by viewing the register, opening IDs, or selecting a returning guest.

`guest_register_history_browser.py` tests 360/390/1440px, foreign dismissal/reveal, portal/copy fallback, historical snapshots, table filters and full record, private photos, returning lead/companion/foreign details, deleted/late/edited IDs, exports, history pagination and draft close. `guest_register.test.cjs` covers record identity and export privacy. Existing check-in, photo, billing, accounting and security suites continue to run. All browser records/photos are synthetic.
