# UAT002 — Master Menu channels (draft)
One master item, global availability, independent Online/POS/Room/QR flags. Existing item defaults preserve behavior; a paused item remains paused everywhere. The QR menu is public when selected: do not enable QR for private room-only items. No existing record is changed in production. Customer discovery, menu and cart refresh use online only; POS and room picker have independent filters. Online checkout, quote, reorder, storefront and publication guards are in rollback-only SQL rehearsal candidate, not a deployed migration. Already paid orders must still finalize from original snapshot. Owner price preview shares online quote endpoint; offline-only owner preview requires separate scoped review. Manual custom items remain authorized operator charges and are not marketplace products.
References: https://support.toasttab.com/en/article/How-to-Manage-your-Menu-Visibility-Settings ; https://supabase.com/docs/guides/database/postgres/row-level-security ; https://supabase.com/docs/guides/database/functions .
Release gates: inspect option-link public policies, direct/legacy checkout grants and Edge Functions; audit role/tenant isolation, QR-only online denial, out-of-stock, old cart, already-paid immutable finalize, POS/room custom billing, old menus; run rehearsal on disposable clone, capture rollback, review advisories, generate proper migration using CLI, then deploy DB first and frontend only after proof. Existing browser fixtures may need schema updates; no merge or production release until all checks pass. User acceptance pending.
