## How statuses work

Lifecycle: `PLANNED → IMPLEMENTED → TESTED → LIVE → ACCEPTED`. A screen may contain released features and unresolved gaps; the lifecycle is a conservative screen-level summary, not an estimate of code completion.

Condition: `VERIFIED COMPLETE`, `PARTIALLY IMPLEMENTED`, `BROKEN`, `MISSING`, `NOT TESTED`, `EXTERNALLY BLOCKED`, `SUPERSEDED`.

No screen is ACCEPTED solely because automated QA passed. `B0` below identifies the audited source/deployment baseline inherited by each screen/action row. `Owner acceptance pending` means no current signed-in real Owner/device certificate was obtained. Candidate test paths identify coverage to inspect; their existence is not evidence of complete acceptance. Every pending row's next action is to execute its listed gap on the current release and attach redacted results. No made-up percentages.
